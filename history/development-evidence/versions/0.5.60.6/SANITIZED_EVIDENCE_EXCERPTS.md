# [IP_REDACTED] B42.19 Structure Damage API Evidence

## Local Evidence Source

```text
PROJECT_ZOMBOID_BUILD=42.19.0

INSPECTION=javap public signatures and WeaponHit bytecode
```

## Event Signature and Ordering

The local JAR contains `OnWeaponHitThumpable` trigger sites in `IsoDoor`,
`IsoWindow`, `IsoBarricade`, and `IsoThumpable`. Every inspected `WeaponHit`
method passes three arguments in this order:

```text
OnWeaponHitThumpable(attacker, weapon, targetObject)
```

Bytecode order proves the event runs before native structure damage:

- `IsoDoor.WeaponHit`: event at bytecode 57-63; native door damage starts at 231.
- `IsoWindow.WeaponHit`: event at 85-91; native damage starts at 130.
- `IsoBarricade.WeaponHit`: event at 26-32; native damage starts at 131.
- `IsoThumpable.WeaponHit`: event at 64-70; native damage starts at 73.

Therefore, applying 20 times the weapon value inside the event would be added to
the later native hit and could become 21 equivalents. The implementation instead
captures pre-hit health and defers settlement until the native health delta is
observable.

## Proven Signatures

Local `javap` confirms:

```text
HandWeapon.getDoorDamage() -> int
HandWeapon.getCondition() -> int
HandWeapon.setCondition(int)

IsoWindow.getHealth() -> int
IsoWindow.Damage(float)
IsoBarricade.getHealth() -> int
IsoBarricade.Damage(float)
IsoThumpable.getHealth() -> int
IsoThumpable.Damage(float)
IsoDoor.getHealth() -> int
IsoDoor.setHealth(int)
IsoDoor.WeaponHit(IsoGameCharacter, HandWeapon)
```

`IsoDoor.Damage(int)` is package-private in the inspected bytecode and is not
treated as a stable Lua-callable public API. The door route therefore uses
`setHealth` while health remains above zero; if equivalent damage would destroy
the door, it leaves one health and performs one guarded engine `WeaponHit` to
commit native destruction side effects. That guarded final hit snapshots and
restores endurance and weapon condition.

## Supported Targets

The runtime accepts only these proven destructible classes:

- `IsoDoor`
- `IsoWindow`
- `IsoBarricade`
- `IsoThumpable` (including player-built thumpables)

Permanent map walls, characters, NPCs, animals, vehicles, projectiles, shoves,
unarmed attacks, and firearms are excluded before settlement.

```text

STRUCTURE_TARGET_CLASS_EVIDENCE=PASS
WEAPON_DOOR_DAMAGE_API=PASS
PUBLIC_STRUCTURE_DAMAGE_API=PASS_WITH_ISODOOR_SPECIAL_COMMIT

# [IP_REDACTED] Green Arc Visual Render and Performance Report

## Arc Transaction

At the final orb position, cached or newly due (250 ms budget) zombie candidates
are distance-sorted and capped at eight. Beam counts are assigned once:

```text
distance <= 3: 3 beams
3 < distance <= 6: 2 beams
distance > 6 within captured range: 1 beam
```

The visual phase lasts 3000 real milliseconds. No kill is submitted on its first
frame. At completion, each still-alive, same-level, in-bounds and in-range
`IsoZombie` receives at most one final lethal commit. Early-dead targets stop
rendering at the next 250 ms validation. Humans are never inserted into the arc
target table.

## Rendering

`XNP_DR_GreenArcVisual.lua` owns one transparent full-screen `ISPanel`. It loads
the locked orb and two beam textures once, then reuses them. Rendering consumes
only the current orb state and cached target objects; it never calls the world
zombie-list scan.

Each beam is a segmented curve. Deterministic sine phase produces curvature and
main-line jitter capped at two pixels. Two additional copies use 1.5-pixel
opposing offsets and alpha 0.24/0.18 against main alpha 0.86, both below the 35%
ratio limit. Different beam phases prevent near-target triple beams from fully
overlapping.

Map display, pause, death, cleanup, main menu, and game exit hide or remove the
visual state. No full-screen post-process is used.

# [IP_REDACTED] Green Orb Movement, Bounce, and Targeting Report

## Runtime Model

The active skill creates one logical orb state, not an inventory item, trap,
explosion, moving player, or persistent world object. It is accepted only by a
left-button double click on the green marker.

At cast time the module records all four screen corners in world coordinates via
the locally verified `Core.getScreenWidth/getScreenHeight/getZoom` and
`IsoUtils.XToIso/YToIso` APIs. The orb cannot leave that fixed world rectangle or
travel farther than the captured screen diagonal.

## Speed

Normal non-sprinting player displacement is sampled over real time and maintained
as an EMA. Once three valid samples exist, that measured tiles-per-second value is
used. Before a displacement sample exists, the locally verified
`IsoPlayer.getMoveSpeed()` value is converted using the engine's 30 Hz movement
step and accepted only inside a conservative 0.4-4.0 world-unit/second range.

```text

ORB_SPEED_PRIMARY=MEASURED_PLAYER_WORLD_DISPLACEMENT
ORB_SPEED_FALLBACK=ISOPLAYER_GETMOVESPEED_30HZ
```

## Target and Collision Rules

The locally verified `IsoCell.getZombieList()` supplies candidates. Every entry
must pass `instanceof(..., "IsoZombie")`, alive/health checks, same-level checks,
and the captured screen bounds. The candidate cache is refreshed no more often
than every 250 ms.

`IsoGridSquare.isBlockedTo(nextSquare)` is the proven wall collision query. The
first collision reflects the blocked movement axis and logs one bounce. A second
collision ends movement and starts the arc. Human objects are never scanned as
targets or collision triggers.

If no zombie exists, the orb remains at the cast origin for 150 ms and starts the
arc. Reaching a zombie, losing the target, timeout, screen boundary, range limit,
or the second wall collision also starts the arc.

# [IP_REDACTED] Green Structure 20-Hit Equivalent Report

## Settlement Contract

`XNP_DR_GreenStructureDamage.lua` registers one `OnWeaponHitThumpable` callback
in single-player authority. A valid event stores target health before the native
hit. The existing central `OnPlayerUpdate` calls its lightweight pending queue;
after native damage appears, it computes:

```text
native_one_hit_damage = health_before - health_after
additional_script_damage = native_one_hit_damage * 19
total_effective_damage = native_one_hit_damage * 20
```

This measures the engine's actual submitted damage, so door/window/barricade
multipliers and the current weapon's `getDoorDamage()` route remain authoritative.
It does not substitute an unrelated fixed damage constant.

## Admission

All conditions must pass:

- attacker is a non-NPC `IsoPlayer` with the green trait;
- green melee enhancement is enabled;
- weapon is a non-ranged `HandWeapon` and not bare hands or a physics projectile;
- attack is not a shove, firearm, vehicle impact, explosion, or active green skill;
- target is one of the proven destructible structure classes;
- the native hit produces a positive health delta;
- the per-hit token has not already committed.

The green tier is captured before the hit. Its configured endurance cost is paid
once after successful additional structure damage. Direct structure damage does
not call weapon-use or condition-loss APIs. The guarded door destruction fallback
restores condition/endurance before the one normal green cost is applied.
